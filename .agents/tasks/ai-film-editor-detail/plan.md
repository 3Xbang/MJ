# Implementation Plan

## Investigation findings, ordered by root-cause priority

- **P0, shot facts are discarded before image/video generation.** `nodes/director/script_full_parser_node.py:147-240` asks phase 1 for a `raw_description` of at most 40 words, then phase 2 receives only that short description plus the scene name and character appearance (`parse_script` around lines 500-587). The phase-2 schema has `action`, `business`, and `emotion`, but the merged shot has no separate facial micro-expression, gaze, action start/process/end, prop interaction, section type, or scene occurrence. `nodes/video/shot_keyframe_node.py:58-112` forwards action, emotion, and lighting but not business, dialogue, prop facts, scene environment, or camera motion. `nodes/video/wan_shot_renderer_node.py:70-95` forwards only the same partial fields. This is concrete evidence for the reported expression, micro-action, scene-detail, and object-confusion risks; the report itself is not treated as proof of the rendered result.
- **P0, camera motion can disappear twice.** The parser schema permits `static` and defaults missing phase-2 motion to `static` at `script_full_parser_node.py:599`; `wan_shot_renderer_node.py:54-85` only emits phrases present in `CAMERA_PHRASES`, so an unsupported or empty motion is omitted and the prompt ends with generic `smooth natural motion`. The keyframe prompt does not include camera motion at all. The current UI mock parser in `tests/ui_mock_server.py` also supplies `camera_motion: "static"`, so the existing E2E test cannot detect this failure.
- **P0, scene grouping retains a physical-name list but loses screenplay semantics.** `_build_scene_map` (`script_full_parser_node.py:80-137`) groups repeated `场景 A` blocks into one physical scene, but it does not preserve block/occurrence order or classify `[黑屏]`, `[快速闪切]`, `[半剪影]`, `[淡出]`, title, intercut, or transition beats. If the LLM assigns all shots to one scene, the fallback at `parse_script` around lines 545-555 distributes shots by round-robin position rather than source block. That can place a London shot in the Thailand scene or vice versa. No code currently distinguishes title/prologue/epilogue/montage from a location.
- **P0, generated props are not connected to first-frame generation.** `AFE_PropsImageGenerator.generate` produces an image batch (`props_image_generator_node.py:150-231`), but `AFE_ShotKeyframeGenerator` has no generated-props input and only loads uploaded prop files from `user_refs` (`shot_keyframe_node.py:201-222`). The stage-3 graph in `webui/graphs.py:104-116` therefore cannot pass the stage-2 generated prop batch to a keyframe. The prompt mentions a prop reference only when that uploaded file exists. This is a direct mechanism for prop omission and cross-shot asset ambiguity.
- **P0, several asset mismatches are silently converted into the wrong reference.** `pick_scene_image` (`shot_keyframe_node.py:115-127`) falls back to scene index 0 when a scene name is not found and falls back to the first view when the selected view is absent. It also caps characters at `MAX_CHARS_PER_SHOT = 3` and props at `MAX_PROPS_PER_SHOT = 2` without reporting the dropped subjects. Scene/prop generation catches exceptions and inserts a white tensor (`scene_image_generator_node.py:311-314`, `props_image_generator_node.py:222-225`) while reporting no failure count. These paths can make a valid-looking but wrong person or location instead of stopping with an actionable report.
- **P1, empty-scene isolation is only prompt-level and is inconsistent.** `SCENE_ENV_SYSTEM` asks the LLM to ignore people, but its input is a block containing people, actions, dialogue, and props. `AFE_SceneAnalyzer` builds `positive_prompt` from the translated scene name/location (`scene_analyzer_node.py:171-172`) rather than the richer `environment_prompt_en`; the image generator uses the latter, so the two scene prompt paths disagree. The scene generator does request `empty scene, no people`, but it does not validate the returned environment text or preserve a stable `scene_id`.
- **P1, duration normalization is thrown away.** `_normalize_durations` calculates weighted durations (`script_full_parser_node.py:254-270`), but `full_shot` sets every `duration_seconds` back to `seconds_per_shot` around line 589. That makes dialogue/action timing and the requested start/process/end plan unreliable even though it is not one of the four reported symptoms.
- **P1, reference invalidation is global in the UI.** `webui/server.py:236-246` exposes one aggregate reference signature, and `webui/static/app.js:214-234` marks whole stages stale when any reference changes. The on-disk signatures are more granular, but the UI does not explain the real affected-shot range. Name-based files are safer than positional files, yet scene identity currently depends on the first scene-name string and has no occurrence/physical-scene manifest.
- **The workflow itself confirms the current boundaries.** `workflow_templates/afe_full_pipeline.json` and `D:\下载\now-03.json` contain the parser, scene/props analyzers, three-view scene generator, cast refs, keyframes, Wan renderer, assembler, and `show_text_party`; their links do not carry generated props into keyframes. `D:\下载\now-02.json` is the analysis-oriented version. `DEPLOY.md` documents the existing five web steps and the one-line RunPod update command. No GPU result was re-verified locally.

## Design decisions

1. **Use one versioned, explicit shot contract as the source of truth.** Add a small pure-Python helper, `nodes/video/shot_prompt_contract.py`, that normalizes a shot without requiring ComfyUI and renders the shared facts for image and Wan prompts. Keep existing flat compatibility keys (`action`, `business`, `emotion`, `camera_motion`, etc.) while adding explicit fields: `schema_version`, `section_type`, `scene_id`, `scene_occurrence_id`, `source_block_id`, `environment`, `time_of_day`, `weather`, `lighting`, `character_names`, `character_facts`, `props`, `prop_interactions`, `dialogue`, `facial_expression`, `micro_expression`, `gaze`, `body_language`, `action_start`, `action_process`, `action_end`, `camera_angle`, `camera_motion`, `camera_path`, and `pace`. Missing screenplay facts remain empty/`null`; they are never invented as a character, prop, or location.
2. **Separate physical-scene identity from ordered screenplay occurrences.** A stable `scene_id` groups repeated instances of the same physical location. An ordered `scene_occurrence_id` and `source_block_id` preserve each return to that location, including A/B intercut. Semantic sections (`title_sequence`, `prologue`, `epilogue`, `montage`, `transition`, and `location_scene`) are separate shot groups even when they have no physical place. The generic parser must detect these classes from heading/cue vocabulary and source order, not from London, Thailand, A, or B literals.
3. **Reject unsafe scene assignment instead of round-robin repair.** The LLM may enrich a source block but cannot invent a scene index. Validate every shot against its source block and stable scene map. If a shot cannot be assigned, keep its source block and emit a failed-shot report that blocks dependent image/video generation; do not silently select scene 1.
4. **Use deterministic camera defaults only when the screenplay lacks a motion instruction.** Preserve explicit camera language; otherwise derive a documented, non-silent motion from the shot semantic (establishing/title: slow push or crane, action/movement: tracking or pan, reaction/dialogue: subtle push or motivated pan, ending: slow pull-back, explicit hold/locked shot: static). Store `camera_motion_source` as `script` or `derived`, validate it against Wan's supported vocabulary, and always render the chosen phrase into the Wan prompt. Static remains legal only when explicitly stated or when the normalized contract marks a deliberate locked hold.
5. **Build both prompts from the same fact list.** The keyframe prompt must include the same environment, named characters, expressions/micro-expressions, body action phases, prop interactions, lighting, framing, dialogue-as-visual-context, and camera facts as Wan. It must say not to render subtitles/text when dialogue is only spoken. The Wan prompt must include start, process, and end states and a camera phrase. A fact-level regression test will compare required terms across both prompts.
6. **Make reference slots explicit and isolated.** Slot 1 is the selected empty scene reference, the next slots are only the named characters in the shot, and the remaining slots are only the named props used by the shot. Pass manifests/IDs alongside batches, use `scene_id`/asset IDs rather than display order, and fail with a report if a requested reference is missing or a batch is ambiguous. Use generated prop images when no uploaded prop image exists; uploaded references override generated candidates for that named asset. No reference is required: text-only assets remain a valid path.
7. **Persist dependency signatures by entity and shot.** Keep the five-step UI and current `analysis.json`, `ui_state.json`, cancellation, and disk-cache model. Add contract/asset manifests and per-entity reference signatures to state. A cast choice invalidates only shots containing that character; a scene view/reference change invalidates only shots using that `scene_id`; a prop change invalidates only shots using that prop; a changed shot contract invalidates its keyframe, video, and final assembly. Preserve existing choice, redo, expiry, and resume behavior.
8. **Use failure reports rather than white placeholders.** Generation nodes may reuse valid cached artifacts, but a failed scene/prop/keyframe/clip must be recorded with asset/shot ID, stage, exception, and remediation. Downstream stages must refuse unresolved dependencies and the web UI must display the node/stage error. `show_text_party` remains in the canvas workflow and no user-facing manual wiring step is added.

## Regression test checklist

- Parser: generic title/opening, black screen, prologue, epilogue/ending, fade/transition, rapid montage, arbitrary named locations, repeated continuous blocks, A/B alternation, and cross-scene intercut order.
- Contract: every shot has structured environment, character, prop, dialogue, expression/micro-expression, action start/process/end, lighting, framing, angle, motion, pace, and source IDs; missing facts stay empty; duration normalization survives the merge.
- Prompt fidelity: the same scene/character/prop/expression/micro-action/camera facts occur in the storyboard/keyframe/Wan prompt representations; dialogue is represented as spoken context without forced subtitle text; Wan never silently loses an explicit or derived motion.
- Reference isolation: scene images contain no people; prop images contain no scene/person; keyframe slot 1 is the selected scene, character slots contain only listed characters, prop slots contain only listed props; uploaded references override generated assets and no-reference text paths work.
- Invalidation: cast, scene view/reference, prop, keyframe pick/redo, camera/action contract, and global style changes invalidate only their documented downstream shots; final assembly becomes stale after a clip change; cancel leaves completed files reusable.
- Failure behavior: missing models, failed scene/prop/keyframe/video generation, missing references, ambiguous batch manifests, and missing keyframes produce clear stage/ID reports and never silently substitute a different scene/person.
- UI/workflow: five web stages remain, project state survives reload/restart, `show_text_party` remains, generated props reach keyframes, graph IDs/links/slots validate, and the current workflow does not require manual rewiring.

## Local and GPU verification boundary

Local verification can cover Python syntax, pure parser/contract/prompt tests, graph validation, mocked persistence/cancellation/invalidation, and the existing browser E2E flow. It cannot prove Qwen/Krea/Wan visual fidelity, face/micro-expression persistence, actual camera motion, model memory use, ComfyUI version compatibility, or RunPod output quality without the installed models and GPU runtime. The implementation must record these as unverified until RunPod acceptance:

1. Run the documented update command or `bash deploy_pod.sh`, restart ComfyUI, and confirm all AFE nodes load without `IMPORT FAILED`.
2. Open `/afe/`, paste the full customer screenplay, leave test mode on, and analyze. Inspect the shot table/report for separate title/montage/transition groups, stable repeated scene IDs, correct A/B alternation, structured expressions/micro-actions, prop interactions, and non-static camera plans.
3. Generate scene/prop/cast assets with no uploads, then repeat with one upload in each slot. Confirm empty scene references contain no people, generated/uploaded references appear in the correct downstream keyframe slots, and changing one asset does not redraw unrelated shots.
4. Generate at least one title/montage shot, one London-equivalent location shot, one second-location shot, one A/B return shot, one facial-reaction shot, and one action shot. Inspect the actual keyframe and Wan clip, the stored prompt/manifest, and the renderer report. Run the full film only after the two-shot check succeeds.
5. Test cancel during scene/keyframe/Wan generation and requeue after ComfyUI restart. Confirm completed artifacts are reused, failed artifacts are reported, and the final assembly refuses unresolved shots.
