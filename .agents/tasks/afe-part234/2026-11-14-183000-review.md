## High-level view

The exception-handling split in `AFE_FaceEnhancer` separates an import-time failure (CodeFormer not installed) from a runtime-API failure (CodeFormer installed but broken), so the warning message now distinguishes between the two cases. `except Exception as exc` in Step 2 is intentionally broad — the `{exc}` interpolation in the warning message means the actual error is still visible in the ComfyUI log.

`AFE_VideoUpscaler` now emits a logger.warning when the user picks "lanczos". The warning fires once per queue execution (not per frame, since `F.interpolate` processes the whole batch), so log noise is bounded.

The `repositories/__init__.py` fix restores `PropsRepository` and adds `AudioRepository` to the public namespace. Any caller importing from `lib.persistence.repositories` directly was silently broken between commits.

The workflow template fixes resolve two structural problems. Template 04's `last_link_id` was one behind the highest existing link ID (18 vs 19), triggering a ComfyUI collision warning on the first user edit. Template 06 had an invalid wiring where a `VHS_FILENAMES` output was fed into `AFE_Watermark`'s `IMAGE` input — a type mismatch ComfyUI rejects at load time — and a downstream SaveImage node that served no purpose in a node-driven export workflow.

### CodeFormer exception path split

The old single `try/except (ImportError, ModuleNotFoundError, AttributeError)` covered both the `importlib.import_module` call and `enhancer.enhance()`. `AttributeError` was doing double duty — catching a missing module attribute at import time and a mismatched API signature at call time — which meant both failure modes produced the same "CodeFormer not found" message even when CodeFormer was installed. The new structure uses two independent blocks: Step 1 catches only `(ImportError, ModuleNotFoundError)` from the import; Step 2 catches `Exception as exc` from the enhancement call and includes `{exc}` in the warning, so a developer investigating a silent passthrough will see the root cause in the ComfyUI console.

### Workflow 04 — last_link_id collision

The template's `last_link_id` was 18, but link ID 19 already existed (`[19, 11, 0, 12, 0, "IMAGE"]` — the AFE_VideoUpscaler→VHS_VideoCombine connection). ComfyUI uses `last_link_id` as the counter for new links; a value below the highest existing ID guarantees a collision on the first user edit. The fix sets it to 19, confirmed by reading the full links array.

### Workflow 06 — topology rewire

`VHS_FILENAMES` is a string tuple of output file paths, not an image tensor. The old topology fed it into `AFE_Watermark`'s `IMAGE` input, which ComfyUI's type checker rejects at load time. The new topology:

```
VHS_LoadVideo ──(IMAGE)──► AFE_Watermark ──(IMAGE)──► VHS_VideoCombine
                │                                            ▲
                └──(AUDIO)───────────────────────────────────┘
```

`last_node_id` drops from 7 to 6 (SaveImage id=7 removed). `last_link_id` stays at 7 — links 6 and 7 existed in the old topology and were removed, so the counter is already past the highest surviving link ID of 5, and no collision can occur on future edits.
